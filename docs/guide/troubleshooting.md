# 故障排查

按“网络 → 鉴权 → 路径 → 模型 → 工具配置”的顺序检查，通常能快速缩小问题范围。

## 第一步：记录现象

保存报错时间（含时区）、工具版本、请求接口、模型 ID、HTTP 状态码和错误体。如果响应头中有请求 ID，一并保留。分享日志前隐藏 API Key、Cookie、访问令牌与私密内容。

## 网络连通性

先访问[控制台](https://api.mugua.link)，再用[快速开始](/guide/start#_3-查询可用模型)中的命令查询模型。

- DNS、TLS 或连接失败：检查设备网络、代理和证书环境，或换用 CF 站（见[线路选择](/guide/base-url#线路选择)）。
- 控制台可用但 CLI 不通：检查 CLI 进程实际继承的代理环境和运行环境，例如 WSL、容器或后台服务。
- 连接成功但长时间无响应：使用短输入重试，检查模型状态和客户端超时设置。

控制台页面打开只说明网页可达；模型查询成功说明鉴权和该接口可用，生成能力还要单独验证。

## 鉴权失败

| 现象 | 检查 |
| --- | --- |
| `401` | Key 是否完整、有效，请求头格式是否正确 |
| `403` | 账户余额、令牌额度上限、模型限制与响应体中的具体拒绝原因 |
| `503` 无可用渠道 | 令牌分组是否提供该模型，见[分组与令牌](/guide/groups) |
| 环境变量已设置但工具读不到 | 工具是否从该终端启动；后台服务是否继承了变量 |
| 修改配置后仍使用旧 Key | 项目配置、启动参数、系统环境变量或网关是否覆盖了设置 |

OpenAI 兼容调用发送 Bearer 凭据；Anthropic SDK 通常使用 `x-api-key`；Claude Code 的 `ANTHROPIC_AUTH_TOKEN` 使用 Bearer。见[鉴权与安全](/guide/auth)。

## 路径与协议

检查日志中**实际请求地址**：

| 目标 | 正确路径 |
| --- | --- |
| 模型列表 | `GET /v1/models` |
| Chat Completions | `POST /v1/chat/completions` |
| Responses | `POST /v1/responses` |
| Anthropic Messages | `POST /v1/messages` |

出现重复的 `/v1/v1` 或两个接口后缀时，按[地址速查](/guide/base-url)修正 Base URL。路径正确但返回不支持时，确认模型和渠道开放了该协议。

## 模型与参数

- 使用模型广场或 `GET /v1/models` 返回的完整 ID，包括大小写和后缀。
- 确认令牌所在分组提供该模型；同一模型在不同分组的效果和稳定性也可能不同。
- 模型能出现在列表中，并不代表支持所有协议和工具能力。
- `400` 或 `422`：先只保留模型和最小输入，再按模型能力添加温度、推理、图片和工具等参数。
- 空文本响应：查看是否返回工具调用、拒绝内容、输出上限或未完成状态，再决定如何处理。

## 流式输出与工具调用

页面一次性显示全部内容时，检查应用服务器和反向代理是否缓冲 SSE。中断或解析失败时，确认使用了正确协议的事件格式，并处理增量数据和终止事件。

编程助手的完整流程还需要工具调用。先在同一模型、同一协议上验证最小请求，再查看失败发生在生成、工具参数解析还是本地执行环节。见[流式输出](/reference/streaming)。

## 余额、限流与重试

本站账户余额不足或令牌额度用尽通常返回 `403`（具体以错误体为准），需先在控制台充值或调整额度上限。`429` 多为频率、并发或上游渠道限流，建议降低并发、遵循 `Retry-After` 并做有限退避重试；若上游在错误体中明确提示配额问题，则先处理配额。

`500`、`502`、`503`、`504` 可以有限重试。超时后先检查调用记录，避免重复执行和重复消耗。策略见[错误处理](/reference/errors)。

## 工具配置生效情况

| 工具 | 建议检查 |
| --- | --- |
| Claude Code | `/status` 中的 API Base URL、凭据来源及当前模型 |
| Codex | `/status` 中的模型、提供商；启动终端的 `MUGUA_API_KEY` |
| OpenCode | `/models` 中的提供商；全局和项目的 `opencode.json` |
| OpenClaw | `openclaw doctor`、`openclaw models status --probe --probe-provider mugua`；Gateway 的环境变量 |
| CC Switch / AIO | 已启用的供应商、代理开关、上游 URL 与请求日志 |
| Cherry Studio | 实际端点、已添加的模型，以及聊天窗口选中的服务商 |

工具启动和本机健康检查只验证了部分链路。发送一条消息并在木瓜控制台“使用日志”中看到对应记录，才能确认这次上游调用。

## 联系管理员时提供

- 报错时间和时区、工具及版本；
- 请求路径、使用的线路、模型 ID、令牌分组、HTTP 状态码；
- 脱敏错误体和请求 ID（如有）；
- 是否可以复现，以及已完成的检查。

这些信息通常足以定位问题，无需共享完整密钥或账号登录信息。可以在[木瓜 API 用户群](https://qm.qq.com/q/Q90cLKHh2k)中联系管理员，群内也会同步模型上新与站点通知。
