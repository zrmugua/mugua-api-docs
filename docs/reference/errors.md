# 错误处理

先记录 HTTP 状态码，再读取错误体中的 `code`、`type` 和 `message`。网关和上游可能使用不同错误格式，相同状态码也可能有不同原因。

## 状态码速查

| 状态码 | 常见含义 | 处理方式 |
| --- | --- | --- |
| `400` / `422` | 参数或内容格式不符合要求 | 检查 JSON、协议字段和模型参数，修正后再请求 |
| `401` | 凭据缺失、失效或格式错误 | 检查 Key 与鉴权头 |
| `403` | 余额不足、令牌限制或模型访问受限 | 读取拒绝原因，核对余额与权限 |
| `404` | 路径、资源或模型不可用 | 检查最终 URL 和完整模型 ID |
| `408` | 请求超时 | 核对执行记录，再决定是否重试 |
| `413` | 请求体过大 | 缩短上下文或减少附件 |
| `429` | 频率、并发或上游渠道限流 | 读取错误体确认；限流降低并发并有限退避，配额问题先处理额度 |
| `500` / `502` / `504` | 服务端、上游或网关异常 | 有限退避重试，持续失败时换线路或联系管理员 |
| `503` | 分组无可用渠道或上游暂时不可用 | 读取错误体；分组问题需换分组，临时故障可有限重试 |

这是常见 HTTP 语义的排查表，实际原因以错误体和控制台日志为准。

## 平台常见错误

下面是木瓜 API 网关自身返回的常见提示，状态码可能随版本调整，请以错误体中的 `message` 为准：

| 提示关键词 | 常见状态码 | 处理 |
| --- | --- | --- |
| 无效的令牌 / 未提供令牌 | `401` | 检查 Key 是否完整、请求头格式是否正确 |
| 令牌已过期 / 已禁用 / 额度已用尽 | `401` 或 `403` | 在“令牌管理”中调整过期时间、状态或额度上限 |
| 用户额度不足（`insufficient_user_quota`） | `403` | 账户余额不足，需要充值 |
| 当前分组下对于模型无可用渠道（`model_not_found`） | `503` | 换用提供该模型的分组或 `auto`，见[分组与令牌](/guide/groups) |
| 令牌无权使用该模型 | `403` | 令牌设置了模型限制，在令牌管理中调整 |

上游渠道返回的错误会透传或包装后返回，格式可能与上表不同。

## 读取错误体

示例仅用于说明结构：

```json
{
  "error": {
    "message": "错误的详细原因",
    "type": "example_error",
    "code": "example_code"
  }
}
```

客户端应兼容字符串错误、字段缺失、非 JSON 的代理响应，以及 HTTP 成功后流内出现错误的情况。

## 什么时候重试

- 参数、鉴权、权限和模型 ID 错误：先修复配置。
- 余额或配额不足：先处理账号额度。
- 短时限流与暂时性服务端错误：限制重试次数，采用指数退避并加入随机抖动。
- 响应有 `Retry-After` 时：按其秒数或 HTTP 日期等待，设置最大等待时长。
- 网络超时、流中断：检查调用记录和已收到的内容，再决定如何恢复。

例如将退避时间设为约 1、2、4 秒并加入随机抖动，最多重试 3 次。此为应用策略示例，按业务超时和上游要求调整。

## 避免重复执行

SDK、网关和应用可能各自带有自动重试，先确认实际总次数。超时并不代表服务端没有执行，重复请求可能产生额外消耗。

工具调用存在外部副作用时，应在应用侧按调用 ID 去重。幂等键、状态恢复等能力需要服务端明确支持后再使用。

## 流式请求

SSE 建立后即使 HTTP 状态为成功，流内也可能返回失败事件。按协议检查错误、未完成状态和最终终止事件。

中断时保留已收到的内容，向用户展示状态，并避免将整段生成自动叠加到已有文本。事件对照见[流式输出](/reference/streaming)。

## 排查与反馈

记录时间及其时区、请求路径、模型 ID、状态码、脱敏错误体和请求 ID（如有）。详细检查步骤与工具配置入口见[故障排查](/guide/troubleshooting)。
